# Sworn v2: the changes to build, exactly

v1 (`v1-mainnet`, launch #2147) was a test deployment: never announced, no integrators. v2 is a fresh deployment of the
three contracts with the fixes from `audits/` (One Dollar Audit of 2026-10-19 and the swarm's launch audit). Everything
not named here stays as it is: ids, rules, windows, thresholds, templates, fixtures, the questionHash document, the
catalog, the card design, the generator and its goldens, the compiler settings. Decisions in this file are final.
The base already carries the owner's change request CR-1 of 2026-10-19: the hive image no longer prints the token id
(no `<text>` element at all; the id stays the metadata name `Sworn #<id>`); generator, `HiveData`, goldens, README and
tests were updated in the base commit, so "goldens unchanged" means the goldens of this base.

## 1. Registry: paid and pool paths

1. **Price cap on every pool draw (H-1, #6).** `claimSponsored(uint16 traitId, uint256 maxPrice)` and
   `upgradeSponsored` is removed (see 4). `_fromPool` routes through `_price(maxPrice)` (revert `PriceAboveMax` as the
   paid paths do) and additionally reverts `PoolDrawTooLarge()` when `price > pool() / 8` or `price > POOL_DRAW_CAP`
   (`uint256 public constant POOL_DRAW_CAP = 2 ether;` in IMD units, four times the 0.5 IMD launch price).
   Tests: pool 10 IMD, price 10 → revert; price 1 with maxPrice 1 → ok; price 1 with maxPrice 0.5 → revert.
2. **Zero price reverts (L-4, #14).** `if (price == 0) revert ZeroPrice();` in `_price` and `_fromPool`.
3. **Pool limiters restored on failure (L-1, #12).** `poolUsed[claimant][traitId]` is cleared in `_clear()` when the
   request ends without a verified trait (`onFailure`, a `Missed` delivery, `abandon`). `lastPoolDay` stays consumed.
   Test: `onFailure` → the same wallet can draw the same trait again the next UTC day.
4. **The IDMD pool path is deleted (L-2, #13).** Remove `upgradeSponsored`, `MAX_SPONSORED`, `idmdSponsored`,
   `IdmdSponsorExhausted`, `NotIdmdHolder` and every test and document sentence about nine draws per IDMD token.
   `claimSponsored` stays for every list member: one draw per UTC day, nine per wallet lifetime, once per trait.
5. **`abandon` on a shared fact (M-4, #10).** `Pending` records the payer (`payer`) for shared-fact requests; `abandon`
   on a shared fact is allowed only for `payer`, after `ABANDON_AFTER`; and `ABANDON_AFTER` becomes
   `Composer.VALID_FOR_SECONDS + 1 days` (31 days) for every request. Test: a stranger's `abandon` at day 15 and at day
   32 reverts; the payer's at day 32 succeeds; the claimant's personal abandon at day 32 succeeds.
6. **Gas floor before the executor preview (M-1, #7).** In `_burnOrRefund`, before the preview:
   `if (gasleft() < (PREVIEW_GAS + BURN_GAS) * 64 / 63 + 50_000) revert InsufficientGas();` and
   `event BurnSkipped(uint256 indexed tokenId, uint8 reason)` emitted on every path that skips the burn (reason 1 preview
   reverted, 2 amount below `BURN_MIN`, 3 fee above `BURN_FEE_CAP`, 4 fee not attached, 5 bridge reverted). Test: a
   claim sent with a gas limit inside the preview window reverts with `InsufficientGas` instead of skipping silently.
7. **`onResult` clears, then verifies; the order is documented (info, #17; lab finding 1 of 2026-10-19).** v1's order
   stays: `_clear` first, then `_check`; a non-conforming delivery emits `Missed` with its reason and the request is
   over (pending gone, the pool limiter restored per item 3), so the claimant can request again at once. There is no
   redelivery for the same `requestId`: the Intake completes a request exactly once (`reference/IntakeV2.sol`
   `complete()` sets `completed` before the callback and records a callback revert as "not delivered"), so a retained
   pending record would only lock the claimant and the limiter until `abandon` (item 5). Replay of an already consumed
   attestation misses (reason 1). `INTEGRATION.md` says so. Tests go through `intake.complete`, never by impersonating
   the Intake, and the mock Intake mirrors the one-completion rule (`AlreadyCompleted` on a second complete): after a
   `Missed` delivery `pendingOf` is zero, `poolUsed` restored, a new request for the same trait succeeds, and a second
   `complete` for the old id reverts in the Intake.
8. **Kind-3 answers must be complete (info, #17).** `_decodeAndJudge` requires `answer.length == head` for shared facts.
9. **`nextSpecId` and community ids widen to `uint256` (L-7, #16)**, with the `traitId` plumbing that carries them
   (`registerSpec`, `specOf`, `upgrade`, `requestSharedFact`, `applySharedFact`, events, the Composer and Renderer
   signatures that take community ids). Catalog ids stay below 10,001. `registerSpec(Spec calldata s, uint256 expectedId)`
   reverts `UnexpectedSpecId(expected, next)` when `expectedId != 0 && expectedId != nextSpecId` (the launch audit's
   front-run). Test: two registrations in one block with the wrong expected id revert; `expectedId 0` always registers.
10. **`deployedAt` is removed** and the `claimSponsored` NatSpec no longer says "From launch" (#17).
11. **`_burnOrRefund` forwards `fee`, not `msg.value`,** and refunds `msg.value - fee` itself before the bridge call (#17).
12. **`totalSupply()`** is added (a counter in `_mint`); no ERC-2981 (#17: there is no treasury to pay royalties to;
    the card trades royalty-free).
13a. **`onFailure` stays unsigned and says so (L-5, #15).** The plane documents no failure signature, so v2 does not
    verify one: `onFailure` keeps clearing the pending record on a call from the Intake only; its NatSpec and
    `INTEGRATION.md` section 3 state that `NoVerdict` is Intake-attributed, not attester-signed. (A signature check
    against an undocumented scheme would reject every failure and leave requests pending for ever.)
13b. **`forceApprove` per iteration is correct, no change (informational).** Intake v2 pulls the fee inside `request`
    (`_collect`, `safeTransferFrom` in the same call, `reference/IntakeV2.sol`), so each iteration's approval is
    consumed before the next is set. Say so in a NatSpec line above the loop.
13. **Transferable card, direct traits frozen at mint (M-3, #9; the owner's decision: keep transfers).** Transfers stay
    as today. Every direct trait (the Curator-read kinds, and 601 per item 14) is evaluated once in `mintCard` and
    stored on the card (`frozenDirect[tokenId]`, one bit per direct trait); `hasDirectTrait(wallet, id)` answers from
    that snapshot for a wallet that has a card and from the live read for a wallet without one (as today, no card
    needed); `tokenURI` and the rendered card use the snapshot. Oracle traits stay facts about the minter:
    `claimantOf` is the minter forever, `tokenOf(minter)` keeps pointing at the card, and only the minter's wallet can
    `upgrade`, claim from the pool or apply a shared fact for it, whoever holds the token; the holder can do none of
    that. The `description` in `tokenURI` ends with "Facts about the wallet that minted it; direct traits frozen at
    mint; transferable." Tests: with the mock curator, flip a membership after the mint → the card's trait stays;
    `transferFrom` works and the new holder's `upgrade` reverts (`NotTheClaimant`) while the minter's succeeds.

## 2. Composer

14. **Trait 601 "Armed" is a snapshot at mint (M-2, #8).** `mintCard` reads `idmd.balanceOf(msg.sender) >= 1` once
    and stores it (`armedAtMint[tokenId]`); `hasDirectTrait(wallet, 601)` for a wallet with a card answers from the
    snapshot; a wallet without a card answers `false`. Catalog text: "Armed: held an IDMD seat when the card was
    minted". Test: mint with a seat, transfer the seat away → 601 stays lit; mint without a seat, receive one → stays off.
15. **Kind-3 panel 11 / quorum 7 (#18).** `panels` for kind 3 (and any ranked or list answer) becomes `11 / 7`; kinds
    1, 2, 4 keep `5 / 3`; kind 5 keeps `11 / 7`. The composed bodies for 1201 and every community T3 spec change
    accordingly (`templates/fixtures/1201-top-32.json` is regenerated and the golden test updated; the questionHash
    document is unchanged, panel fields are outside it).
16. **Finality margin (#21).** `validateSpec` requires `toBlock <= block.number - 64` for kinds 1 to 4. Test:
    `registerSpec` with `toBlock = block.number - 1` reverts, with `block.number - 64` passes.
17. **The curator argument is used.** `catalogSpec` takes the Registry's `curator` instead of the `MAINNET_CURATOR`
    constant, or the Registry constructor asserts `curator_ == Composer.MAINNET_CURATOR` (choose the first; the constant
    may stay for documentation) (#14).
18. **T3 question text for community specs** is the v2 wording of `TEMPLATES.md` (group by the indexed argument, the
    sort and tie rule, "an entry that is not an address is a wrong answer"). The 1201 catalog text is composed by the
    same code, so it changes too and its fixture is regenerated.

## 3. Renderer

19. **`Buf` accumulators (M-5, #11; lab finding 2 of 2026-10-19).** `_oracle()`, `_communityAttributes()` and `_list()`
    use the growable `Buf` that `image()` uses; a gas test at the caps asserts a cold `tokenURI` under 8,000,000 gas.
    The caps are the largest state the contracts accept, not short fixtures: 25 catalog traits lit, a stored shared
    fact, and 32 community specs each at the maximum `validateSpec` admits (`item` 256 bytes, `name` 32 bytes, `arg`
    32 bytes, `fixedArg` 32 bytes, `sumArg` 32 bytes where the kind allows it). If the accumulators alone do not reach
    the target at that state, the read path changes too: `tokenURI` reads only the spec fields it prints (no copy of
    whole `Spec` structs through `cardOf` / `specOf` for the image), with the output bytes unchanged (the goldens still
    pass). `test/NOTES.md` records the measured gas at that state.
20. **Table tiling check (#17).** A test asserts that the generated `TemplateData` / `HiveData` tables tile with zero gap
    and zero overlap, and `tools/gen_template.py --check` asserts the same.

## 4. Constructor

21. `require(IERC20Metadata(imd_).decimals() == 18)` (L-3); code-length checks for `renderer_`, `composer_` and a nonzero
    `burnExecutor_` outside the empty-floor branch (L-6); the floor branch stays as documented (#14).

## 5. Documents

22. `README.md`, `CONCEPT.md`, `CATALOG.md` (601 wording, panel table, no IDMD sentence, the 31-day abandon window,
    `totalSupply`, the UTC-day pool bucket is a calendar day and not a rolling 24 h), `INTEGRATION.md` (new signatures, `BurnSkipped`, the order of `_clear` and `_check` in `onResult` and that a `Missed` request is over, `expectedId`, 11 / 7, the
    finality margin), `TEMPLATES.md`, `DISCLOSURE.md` (a "v2" section: what changed since v1, and that v1 is a test
    deployment), `test/NOTES.md` (every change with its test). `DEPLOYMENTS.md` is written by the entrant after the
    launch.

## 7. Site (the frontend stage; `web/` is the reviewed public site of v1)

`web/` is the site as delivered by the swarm and reviewed by the entrant (Vite + TypeScript; `npm ci`, `npm test`,
`npm run build` exports to `web/dist`; copy that export to the root `dist/`). Do not rebuild it from scratch; change it:
23. The three addresses and the launch record: `web/addresses.json`, `web/public/data/addresses.json`,
    `web/public/data/launch-record.json` and the constants in `web/src/pages.tsx` take the v2 Registry, Composer and
    Renderer from `.imd/reads/deployment.json`; `web/public/examples/read-registry.sh` too. Every ABI under
    `web/src/abi/` is regenerated from the v2 build (`scripts/check-abi.mjs` must pass).
24. The copy follows v2: the card can be sold, its facts cannot change hands (the buyer note becomes "A card can be
    sold; its facts are frozen at mint and stay about the wallet that minted it, which alone can add traits"); Armed
    (601) reads "held an IDMD seat when the card was minted"; the IDMD pool path and
    its nine-per-token sentence disappear; the shared-fact block says "panel 11 / quorum 7, every attempt costs the
    full price"; the abandon window reads 31 days; `claimSponsored` and `registerSpec` take their new arguments
    (`maxPrice` from the live `priceOf`, `expectedId` from `nextSpecId`).
25. Above the pool-claim button the live Intake price and `pool()` side by side, with a warning when the price exceeds
    an eighth of the pool (the contract reverts above it in v2; the page says so before the click).
26. A v1 note on the About page: "v1 (Registry 0x39bec764…95a6) was a test deployment, superseded by v2 on <date>."
27. `npm test` green, the export has no console error at 1280 and 390 px, en-US numbers, live reads from a public RPC;
    the Explorer renders the wallet result and the card for an address that holds one (a metadata decode error shown
    in place of a result is a blocker; lab finding 3 of 2026-10-19).
